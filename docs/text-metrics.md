# 保存PPTXの文字領域検査

`check_layout.py`は、保存されたPPTXの書式から**行単位の推定矩形**を作る。
PowerPointの描画結果そのものや、文字の黒い画素の外接矩形ではない。
実レンダリングと全ページの目視確認は、引き続き必要である。

## 読み取る値

- runごとの文字サイズ、太字、東アジア／ラテン書体。異なる書式を最大サイズの一律指定へ置き換えない。
- 段落ごとの左／中央／右寄せ、行間の倍率または固定ポイント、段落前後の間隔、左右と先頭行の字下げ。
- 通常図形の四辺の余白と上／中央／下の縦位置。表セルはセル余白を除いた領域を渡し、二重に引かない。
- 段落、`a:br`による手動改行、空段落、自動折り返しの区別。折り返し無効の文字は幅を切り詰めない。
- 保存された自動縮小率と行間削減率。ただし、rendererはOffice任せの自動縮小を使用しない。

runの明示値を優先し、段落の既定run書式、text bodyのリスト書式、slide masterの
`otherStyle`の順で補う。対象は本プロジェクトが生成する通常図形と表セルであり、
任意の外部PPTXのplaceholder継承やテーマフォント名の解決を保証するものではない。
対応外の書体や配置を黙って別の値へ置き換えず、`TEXT-METRICS`として不合格にする。
対応family・face・可変軸は[フォント契約](font-contract.md)に従う。

## rendererとの役割の共有

`add_text(..., role=...)`は`natural`、`body`、`compact`を受け取る。
既定値は太字が`natural`、通常文字が`body`で、表セルは`compact`である。
`fit_text_or_raise()`で役割を指定したrendererは、描画時にも同じ役割を渡す。

役割は`a:bodyPr/a:extLst`の独自拡張へ保存する。表示文字、shape名、既存の品質マーカーを変更せず、
他の拡張情報も保持する。役割情報のない旧PPTXは通常図形が`body`、表セルが`compact`となる。
古い成果物の検査を厳密に再現する必要がある場合は、同じ入力から再生成する。

均一書式はrendererと同じ`wrapper_for_role()`で折り返す。混在runは各書式の幅を加算し、
保護語、禁則、役割別の最終行比率を適用する。Noto書体の日本語／ラテン文字間の間隔もrun境界を含めて測る。
行ごとに矩形を持つため、左寄せ段落と右寄せ段落の間の空白を塗りつぶした衝突判定にしない。

## 判定と限界

行送りは保存された行間と行内の最大サイズから求める。推定矩形の高さはその行の最大フォントサイズとし、
正の行送り余白を上下へ半分ずつ配分する。行送り全体を文字の描画高さとは扱わない。
段落前後の間隔と空段落は縦位置の計算へ含めるが、空文字の衝突矩形は作らない。

- `TEXT-OOB`：通常図形の推定文字矩形が余白内の文字領域から0.03インチを超えて出る。
- `CELL-OOB`：表セルの推定文字矩形がセル内側から0.01インチを超えて出る。
- `T-T`：行同士の衝突。同じtext frame内の過小な行間も検査する。
- `TEXT-METRICS`：対応外書体、明示書体を解決できない文字、均等配置、異常な保存値など。

実グリフの上下端、ベースライン、Office独自の段落処理を完全に再現するものではない。
文字の視認性、細かな行位置、意図した改行、書体の実際の代替はPNGでも確認する。
機械検査が合格したことだけを提出品質の根拠にしてはならない。

## 検証手順

リポジトリルートから実行する。

```sh
python -m tests.test_text_roles
python -m tests.test_text_metrics
python -m tests.test_check_layout
python -m tools.quality.text_metrics_cases build out/text-cases
```

`text_metrics_cases`は正常4ページと意図的NGの1ページを生成する。正常ページに誤検知がなく、
最終ページのはみ出しと行衝突を拒否できることを検査し、各行の文字・矩形・行送り・役割・書体識別情報を
`report.json`へ記録する。真値付き単体テストは、保存・再読込したPPTXの書式と設計値を比較する。

CIでは同じSHA256の固定Noto Sans JPを使用し、WindowsとUbuntuでそれぞれPPTXと基準値を生成する。
Pillowの測定エンジンはBASICを明示する。wheelのRAQM同梱有無によって既定値が変わることに依存しない。
続いて両OSが双方のPPTXを読み直し、行数、文言、幅、高さ、配置、診断結果、書体識別情報を比較する。
数値の許容差は0.00001インチ。OS／Pythonバージョン、最大差、差の所在は成果物へ残す。
これは同一入力の検査再現性のテストであり、異なるOffice backendの描画一致を意味しない。
