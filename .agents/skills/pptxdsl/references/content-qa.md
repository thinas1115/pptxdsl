# 内容QA

`content.json`へ成形する前と、レンダリング後の内容確認で使用する。

## 入力の確認

- テーマ、想定読者、資料の目的、必須内容、情報源、枚数目安を特定する。
- 誰が何を判断・理解・実行できれば成功かを1文で定義する。
- 必須内容ごとに根拠となる情報源があるか確認する。現在値、制度、価格、仕様など変わり得る情報は、利用者が許可した最新の一次情報で確認する。
- 出典のない数値、日付、固有名詞、組織構成、製品仕様を推測しない。表示に不要な任意情報は省略する。
- 画像が主メッセージになるページでは、利用可能な画像と利用条件を先に確認する。未準備の画像パスを作らない。

## 構成の確認

内部作業用に、必須内容とページの対応表を作る。利用者が求めない限り成果物へ含めなくてよい。

| 確認項目 | 判定基準 |
|---|---|
| 網羅性 | 必須内容のすべてに対応ページがあり、黙って落としていない |
| 一貫性 | 用語、比較軸、追跡単位、期間、単位がページ間で一致している |
| 根拠 | 主張、数値、固有名詞が指定情報源へ戻れる |
| 読者適合 | 前提知識を飛ばさず、判断や理解に必要な順序になっている |
| 重複 | 同じ主張を見た目だけ変えて繰り返していない |
| 不確定事項 | `TBD`、`要確認`、仮の担当名や数値が完成資料に残っていない |

専門用語を初めて使う場合は、詳細図や手順より前に定義する。結論をタイトルへ押し込まず、タイトルは主題、結論や読み方は`lead`、根拠は本文へ分ける。

## レンダリング後の再確認

文字が読めるだけでは内容QAの合格にしない。スライドごとに、タイトルが本文の主題と一致するか、図の線・向き・ラベルが情報源と一致するか、数値と単位が欠けていないかを原寸画像で照合する。
