# PNGの合否基準と検証記録

新規資料・renderer変更の両方に適用する。機械検査の成功、PNGの生成、目視QA、人の承認は別の状態として記録する。

## 自動検査と目視の境界

| 対象 | PNGから補助検査できる範囲 | 必ず目視する点 |
|---|---|---|
| 文字 | 単独の文字領域に限り、指定色の実画素が期待枠の外へ出ていないか | 文字切れ、欠字、フォント置換、禁則、読めない小文字 |
| 線 | 連続線の既知の通過点に指定色の実画素があるか | 矢印方向、接続先、経路全体、自己処理、差戻し、ラベル背景による線欠け |
| ページ | 全ページのPNG名・枚数・寸法の一致 | 内容欠落、密度、余白、整列、ページ間の一貫性 |
| 色 | 今回の補助検査は指定色との画素照合だけ | 文字と背景のコントラスト、意味の区別、選択・強調の正しさ |

PNGの文字はOCRせず、PPTXの文字実測モデルも使わない。画像・罫線・別の文字が混じる領域では、
画素を文字の一部と断定できない。検査領域は回帰テスト側で対象を分離して定義する。
枠内で切れて消えた文字、欠字、指定されていない箇所の線欠けは検出できない。
補助検査だけの合格を「画像品質合格」「全ページ目視済み」と表現しない。

## NG基準

- 文字切れ、欠字、意図しない枠外描画、文字・図・線の意味を変える重なりは、1箇所でもNG。
- 接続先を追えない、矢印が逆、ラベル背景が自己処理・差戻し線を消す場合はNG。
- rendererが定めた最小文字サイズ未満への縮小、フォント置換、原寸で読めない文字はNG。
- 意味を持つ通常文字は背景とのコントラスト比4.5以上、18pt以上または太字14pt以上は3以上を目安とし、
  未達や判読困難な箇所は修正する。意味のない補助罫線には同じ下限を強制しない。
- 背景に接する意味面は既存の`VIS-CONTRAST`基準にも合格すること。
- 数値・単位・固有名詞・強調対象・参照先が情報源と異なる、または根拠がない場合はNG。

判定できない箇所は「未確認」であり合格ではない。原寸はPNGを間引かず、ページ全体に加えて接続点や
線上ラベルを局所確認する。一覧だけ、変更箇所だけを見て全ページ確認済みとしない。

## Backend差と再確認範囲

PowerPointがある環境ではPowerPointで受け入れ確認する。PowerPointのないCIはLibreOfficeなどで
代替確認し、製品・バージョン・書体・未確認のPowerPoint描画を明記する。代替結果をPowerPoint確認済みへ昇格しない。
フォント校正・PDF文字位置の検査は独立した測定根拠であり、PNG目視を置き換えない。

OSやbackendをまたぐ完全な画素一致は要求しない。影や字形の輪郭差は記録し、意味・可読性・接続関係を確認する。
同一backendの再描画でも差はあり得る。既確認画像を再利用する場合は、同じPPTX内部値・素材・書体・描画条件を
照合する。ハッシュ一致なら既確認の原寸結果を引き継げる。ハッシュ不一致は変更ページとして原寸再確認する。
例外として、PPTX内部が同一で、前景差がすべて1画素近傍内と検証できる輪郭の微差は、その根拠・最大差を記録して
前回の原寸結果と最新一覧を併用してよい。文字や線が1画素移動してよいという一般許可ではない。

修正後はPPTX生成・機械検査・PNG化を再実行し、全ページ一覧と影響ページの原寸を再確認する。
共通部品・フォント・テーマを変えた場合は、全type・通常/lead・最小/最大/過密入力まで影響範囲を広げる。

## PNG補助検査の実行

回帰用の検査仕様がある場合だけ実行する。資料内容の`content.json`へ検査座標を追加しない。

```text
python slidegen/raster_qa.py out/raster-checks.json out/png --report out/raster-report.json
```

検査仕様の最小例（1600×900の実PNGに合わせた、他要素が混じらない回帰用領域）:

```json
{
  "version": 1,
  "backend": {"name": "libreoffice", "version": "実際のバージョン"},
  "pages": [{
    "png": "slide_01.png", "size": [1600, 900],
    "checks": [{
      "id": "isolated-text", "kind": "ink_bounds",
      "region": [60, 60, 800, 300], "bounds": [100, 100, 600, 200],
      "ink": "182C43", "tolerance": 24, "allowance_px": 1, "min_pixels": 5
    }]
  }]
}
```

`region`は調べる矩形、`bounds`はその中で文字の実画素が入るべき矩形。値は`[左, 上, 右, 下]`のPNG画素で、右・下は含めない。
指定色から各RGB成分の差が`tolerance`以内の画素を数える。既定24、0〜255を指定できる。
枠外判定にはアンチエイリアス用に既定1画素の余裕を置く。`allowance_px`は0〜3だが、失敗を隠す目的で増やさない。
`ink_presence`は`region`内に`min_pixels`以上の指定色画素があることを検査する。線の通過点を小さな領域で指定する。
破線の空白や交差点を通過点に選ばない。複数箇所を検査する場合はルールを追加する。

全ページを`pages`へ列挙する。対象画素の検査が0件なら`incomplete`で失敗し、成功にはしない。
自動結果は対象箇所だけの判定であり、記録の目視・PowerPoint目視・人の承認は常に未実施のまま返す。

## 検証記録

`out/visual-qa.md`またはPRに、少なくとも次を残す。利用者固有の絶対パスや個人情報は書かない。

```text
対象: 入力・PPTX・PNGの相対名、commitまたはSHA256、ページ数
環境: OS、Python、描画backendの製品名/実バージョン、Officeバージョン（未使用は未使用）
書体: 実family、Regular/Bold、可変軸、代替・置換の有無
機械検査: validate/check_layout/対象テストの結果
PNG補助検査: 対象ルール数・結果、未実施なら理由
一覧: 確認範囲・結果
原寸: 確認ページ、既確認結果の再利用と一致の根拠
接続経路: 確認した経路・ラベル前後・自己処理・差戻し
確認者: AIまたは人の役割、確認日（個人名は不要）
backend差・未確認事項: なし、または具体的な制約
判定: 合格 / NG / 未確認（機械・目視を別記）
人の承認: 未依頼 / 承認待ち / 承認済み（実際の承認だけを記録）
```

AIは実際に見た範囲の目視結果を記録してよいが、人の承認を代行しない。
公開・提出時の情報の正確性や利用可否は資料の責任者、renderer変更のマージはリポジトリ保守者の承認点である。
利用者が既に承認した情報・条件は再承認を求めず、未決の判断だけを提示する。
