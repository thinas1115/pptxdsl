# 概念説明に使う生成画像

## 使い分け

概念の比喩、現象のイメージ、文章だけでは伝わりにくい場面には生成画像を使える。
正確なノード数・接続・送受信方向・寸法・数値が判断材料なら`diagram`、専用type、実データのグラフを優先する。
生成画像を実在の構成・製品画面・実測結果・情報源の代わりにしない。AWS公式アイコンを画像生成で作り直さない。

## 資料共通の画像テーマ

画像ごとに「シンプル」「AIっぽくなく」と依頼するだけでは統一できない。
生成前に、テンプレートと利用者の意図に合う共通スタイルを一度決める。
背景はPPTX生成と同じConfigの`slide`から読み込む。画像用JSONへ背景色を複写しない。
全画像で、解決した背景条件、色数・色値、線・塗り、文字、余白、禁止装飾を共通化し、変えるのは説明内容だけにする。
スタイルは`content.json`の外に保存する。利用者が指定した表現を優先し、全資料へ同じ絵柄を強制しない。

`image-style.json`の例（文字・輪郭色は実際の背景に対して読める配色にする）:

```json
{
  "palette": "主線と文字 #182C43、強調 #0D7870、補助 #D1CFC8。色を追加しない",
  "drawing": "フラットな説明図。均一な細めの輪郭線、単色塗り。全図で同じ線とアイコンの描き方",
  "lettering": "日本語ゴシック、紺色。ラベルの文字量と太さを揃え、指定の文字だけを描く",
  "composition": "横長。要素を中央にまとめ、外周の余白と情報密度を揃える。タイトルやフッターは描かない",
  "avoid": "発光、ネオン、影、立体球体、ガラス質感、紙のテクスチャ、不要な配線、架空のロゴ"
}
```

`image-briefs.json`には図ごとの内容だけを書く。スタイルの上書きは書かない。

```json
[
  {
    "id": "role",
    "intent": "スライドと生成図解の役割の区別",
    "elements": ["スライド全体の枠", "中に配置する完成図解"],
    "relationships": ["スライドの中に図解を配置する"],
    "labels": ["スライド", "図解"]
  }
]
```

同梱の補助スクリプトで、全プロンプトに同一の共通指定を付ける。
`<Skill>`は実際のSkillフォルダへ置き換える。cloneでは`.agents/skills/pptxdsl`。

```text
python <Skill>/scripts/build_image_prompts.py --style image-style.json --briefs image-briefs.json --template-config template.json --output image-prompts.json
```

出力の`prompts[*].prompt`を省略せず画像生成へ渡す。共通指定とそのSHA-256も記録される。
`--template-config`にはPPTX生成と同じファイルを渡す。省略時はPPTXと共通の標準設定を読み込む。
本文の背景色を使い、表紙用の`cover.background_color`は使わない。

- 単色背景では`slide.background_color`をプロンプトへ自動反映する。
- `slide.background_image`がある場合は透過PNGを指定する。出力の`transparent_background: true`を
  生成ツールの透過設定にも反映し、採用PNGのアルファ透過を確認する。市松模様を描いた画像は透過ではない。
  透過出力に対応しない環境では、その制約を伝え、固定色で塗りつぶして完了扱いにしない。

Configを変更したらプロンプトを組み直し、背景・文字のコントラストを再確認する。
旧背景色を焼き込んだ画像は新Configへ追従しないため、その画像は再生成が必要。
旧背景と矛盾する参照画像を使い回さず、新背景に合う最初の画像を採用してから後続の参照にする。
これはプロンプトを整形するだけで、画像生成APIを呼んだり、生成済みと判定したりする機能ではない。
絵柄を変更するときは共通スタイルを更新し、影響する全画像へ適用する。1枚だけ別の絵柄へ差し替えない。

## 生成と採用

1. そのページで説明する概念、伝える関係、画像では示さない事実を整理する。
2. 上記の共通指定を付け、実環境にある画像生成ツールを使う。対応する画像生成Skillがある場合はその手順に従う。
   ツールがなければ、下記のプロンプトと必要な画像条件を利用者へ渡す。未生成を生成済みと報告しない。
   最初に1枚を生成して絵柄を確認し、採用後は可能ならその画像を後続生成のスタイル参照にも使う。
   参照元の図の内容・文字まで後続画像へ複製しないよう、説明内容を明示する。
3. 生成画像を原寸で見て、要素の不足・重複、誤った方向や因果、不要な装飾、文字化け、商標の捏造を確認する。
   伝える関係が曖昧なら採用せず、プロンプトを具体化して作り直すか編集可能な図解へ戻す。
4. PNG/JPEGを利用者の作業領域の`assets/generated/`へ保存する。透過が必要な素材はPNGにする。
   生成条件と採用判断は同じ領域の記録へ残し、Pluginの同梱ファイルを変更しない。
5. `image`の`alt`へ意味を、必要な説明を`lead`へ書く。ラベル・矢印を含む図は完成画像として取り込む。
   図中文字は原寸とスライド表示の両方で確認する。画像内の物体認識や編集可能な矢印の自動接続、
   図形への自動変換、自由座標指定は行わない。特定サービスのAPIキーや有料契約を必須にしない。
6. 全画像を並べ、背景色、パレット、線の太さ、文字、余白、密度が揃っていることを確認する。
   同じプロンプトだけで一致を保証せず、外れた画像は同じ共通指定と参照画像で生成し直す。

## プロンプトの出発点

以下の可変部分を資料要件で埋める。「AIっぽくなく」「シンプル」だけで依頼を終えず、見た目の条件へ具体化する。

```text
業務資料の概念説明に使う画像。
説明する概念: （利用者の要件）
伝える関係: （要素同士の関係・読み順・対比を具体的に）
必要な要素: （概念を説明するのに必要なものだけ）
共通スタイル: （資料共通の指定を一字一句変えずに付ける）
ラベル: （正確に描く文字を列挙。不要なら文字なしと指定）
完成画像として、要素・ラベル・矢印を含める。タイトルやフッターは含めない。
科学的・技術的な構造を推測して追加しない。
```

利用者が写真・写実・別の絵柄を求めた場合は、その意図を優先する。上記の表現を全資料へ固定しない。
記録には共通スタイルとSHA-256、画像の相対名、説明する概念、実際のプロンプト、参照画像、
生成ツール・実際に分かるモデル名、生成日、採用PNGのSHA-256、利用条件の確認状況、採用前QAを残す。
実在しないモデル名、出典、一律のライセンスを作らない。
PPTXの再生成時は採用済みPNGを再利用し、画像生成を毎回やり直さない。

## 取り込み

画像名を`generated/concept.png`とする例。`--asset-dir`は`assets/`を指定する。
同梱の公式アイコンは従来の指定を維持できる。

```text
python slidegen/validate_content.py content.json --asset-dir assets
python slidegen/generate_from_json.py content.json out/deck.pptx --asset-dir assets --template-config template.json
python slidegen/check_layout.py out/deck.pptx
```

Release版は利用者の作業領域から次のように実行する。`<Skill>`は実際のSkillフォルダへ置き換える。

```text
python <Skill>/scripts/run.py validate content.json --asset-dir assets
python <Skill>/scripts/run.py generate content.json out/deck.pptx --asset-dir assets --template-config template.json
python <Skill>/scripts/run.py check out/deck.pptx
```

`content.json`の該当ページ:

```json
{
  "type": "image", "kicker": "概念", "title": "概念の全体像",
  "image": "generated/concept.png", "fit": "contain", "alt": "画像が説明する概念と関係"
}
```

外部素材は指定ルート内の相対パスだけを受理する。`../`による脱出、絶対パス、ルート外へのシンボリックリンクは拒否する。
同じ相対名が利用者素材と同梱素材の両方にあれば利用者素材を優先する。画像はPPTXへ埋め込まれる。
生成画像を使用しても、全ページPNG化と目視QAは省略しない。
